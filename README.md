# SHINOBI COUNTER LAB · 火影积分赛破阵实验室

> 非官方、社区驱动的《火影忍者》手游积分赛对策检索器。无需识图、账号、模拟器、后台服务或安装依赖。**开源的是程序与结构化案例索引，不是原视频或原作者素材。**

[快速试玩](#本地试玩) · [添加破阵案例](CONTRIBUTING.md) · [字段规范](docs/DATA_SPEC.md)

## 为什么做它？

积分赛阵容变化频繁，攻略散在视频和转载帖里。老玩家知道“某三号位、某特殊开局、某跨度”该怎么处理，新手却只能反复求助。本项目把攻略转成**可检索且附来源的候选方案**，用透明的条件而不是“必胜率”推荐。

## 当前版本 V0.2（2026-10-22）

- **20** 条可溯源阵容记录（含 3 条同一攻略中的明确替代配队），其中 **15** 条允许参加前端检索，**4** 条待人工核验，**1** 条历史档案；另有 **4** 条不完整的攻略线索。
- 三站位输入（支持自定义忍者文本及常见简称），按实际站位匹配；无匹配时提供**严格标注的同三号位参考**，绝不伪称精确克制。
- 双口径计算跨度 `(对方战力-我方战力)/我方战力` 或 `/对方战力`，**未确认原作者跨度分母时不自动据此判断必胜**。
- 防守反查；针对**已收录策略**寻找覆盖更少的换位候选，而不是预测防守胜率。
- 忍者池是可选的折叠高级过滤；本地战报存储/JSON 导入导出兼容 V0.1 数据。
- 完全静态、离线运行、无账号和游戏接口。

> **重要：** 20 条里包括转载与尚未复核案例，**不意味着有 20 套已证实有效的现版本破阵公式**。同一攻略中转载、昵称不清、版本失效等问题都保留了标记。

## 本地试玩

直接双击 `index.html`；或者在本目录运行：

```bash
python scripts/build.py
python -m http.server 8000
```

然后打开 <http://localhost:8000>。开发时修改 `data/*.json` 后执行 `python scripts/build.py` 刷新静态页。

## 目录

```text
├── index.html                     # 预编译单文件，离线可打开
├── src/index.template.html        # UI 模板 + 纯原生 JS
├── data/
│   ├── cases.json                # 带来源、站位、限制与审阅状态的案例
│   ├── heroes.json               # 已知角色与常见别名
│   └── research-queue.json       # 缺少完整对阵的攻略线索
├── scripts/build.py              # 从 JSON 编译纯离线 HTML
├── tests/test_data.py            # 数据校验门槛
├── docs/DATA_SPEC.md             # 数据模型与审核规则
├── CONTRIBUTING.md               # 投稿/校对流程
├── .github/workflows/ci.yml      # PR 校验
└── .github/workflows/pages.yml   # GitHub Pages 自动发布
```

## 数据来源 / 合规

案例来源见 `data/cases.json` 的逐条 `url`，包括抖音原帖及 233 乐园转载；转载内容可能存在误分类/错误。程序不内置视频、图像或攻略原文，不扫描登录页面，不绕过反爬或付费权限。添加新案例时请尽可能链接首发来源，并取得素材使用许可。涉及昵称歧义或非对应版本，必须标为 `hold` 或 `archive`，而不是凑数。

本工具为非官方社区项目，与游戏发行方无关；游戏名称、角色名称归各自权利人所有。
